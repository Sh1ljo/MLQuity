MLQuity: Step-by-Step Guide

Building López de Prado's Advances in Financial Machine Learning in Python, applied to US equities on daily bars.

How to use this guide

Work through the phases in order. Each phase has the same parts, so you always know where you are:

1. ReadThe book chapter(s) for that phase.
2. UnderstandA plain-English explanation of the idea.
3. BuildNumbered Python steps, each with a snippet.
4. CheckA concrete test that tells you it works.
5. AvoidThe mistakes that most often break it.

Rules for every phase:

  • Write the module under src/ and tests under tests/. Notebooks are for poking at results, not for the code you keep.
  • Never edit anything in data/raw/. Write derived data to data/processed/.
  • Every time you try a configuration (a threshold, a window, a model setting), add a row to trials.csv, including the ones you throw away.
  • Run your tests before you move on. A phase is not finished until its checkpoint passes.

The code in this guide is a simplified teaching version. It shows the logic clearly rather than matching the book's code exactly. Where the book gives a more careful version, use it, and treat these snippets as a way to understand it first.

Python primer for this project

You do not need to be an expert. These are the handful of patterns that appear in almost every step.

The five things you will use constantly

  • A Series is one column with a label (the index) on each row. Prices by date are a Series with dates as the index.
  • .loc vs .iloc: .loc selects by label (a date), .iloc selects by position (row 0, row 5). Mixing them up is the most common silent bug, so be deliberate.
  • .shift(1) moves values down one row. It is how you make today's row use yesterday's information. This is the main defence against look-ahead bias.
  • .pct_change() gives the simple return from one row to the next. np.log(price).diff() gives the log return.
  • Vectorisation: series * 2 or a + b works on every row at once. Use plain for loops only when the logic depends on the previous row (like the CUSUM filter), because loops are slower and easier to get wrong.

Phase 0: Data and baseline strategies

Read: Ch 1-2 (skim)  ·  Build: src/data.py, a baseline backtest  ·  Done when: a backtest runs from start to finish.

The idea

Before any machine learning, you need two things: clean data, and a simple strategy to beat. If you cannot beat buy-and-hold, a complex model is just noise. The baseline is also your test harness: you prove the backtest machinery works on something you already understand.

Bars are the unit of time you trade on. This project uses daily bars: one row per trading day with the open, high, low, close, and volume.

  1. Write the loader with strict checks

    The loader should refuse bad data loudly. A silent fix hides problems that show up later as strange results.

    # src/data.py
from pathlib import Path
import pandas as pd

def load_prices(path: Path) -> pd.DataFrame:
    df = pd.read_csv(path, parse_dates=["date"])
    df = df.set_index("date").sort_index()
    if df.index.duplicated().any():
        raise ValueError(f"Duplicate dates in {path}")
    if df["close"].isna().any():
        raise ValueError(f"Missing close prices in {path}")
    return df[["close"]]

    Note on data sources: free sources are convenient but usually leave out delisted companies. That is survivorship bias (see the pitfalls section). Decide on your data source deliberately before you build on it.

  2. Buy-and-hold baseline

    Daily return is the percentage change in close. The equity curve is the running product of (1 + return).

    import numpy as np

ret = prices["close"].pct_change()
bh_equity = (1 + ret).cumprod()

  3. Momentum baseline, without look-ahead

    The signal says "buy if the past 12 months were positive". The critical detail is .shift(1): you can only act on a signal the next day, after the close that produced it.

    mom = prices["close"].pct_change(252)               # return over ~12 months
signal = (mom > 0).astype(float).shift(1).fillna(0.0)  # trade tomorrow on today's signal
strat_ret = signal * ret

  4. Write a Sharpe ratio function

    Sharpe is mean return divided by volatility, scaled to a year. With daily data, multiply by the square root of 252 (trading days per year).

    def sharpe(r: pd.Series, periods: int = 252) -> float:
    return r.mean() / r.std() * np.sqrt(periods)

print("Buy and hold:", sharpe(ret.dropna()))
print("Momentum:    ", sharpe(strat_ret.dropna()))

  5. Start the trials log now

    Create trials.csv with a header, and add a row for each configuration you run. You need this for Phase 7.

    trial_id,date,description,lookback,sharpe
1,2026-10-13,momentum baseline,252,0.00

Checkpoint

  • The loader raises an error when you feed it a file with a duplicate date.
  • Both baselines produce an equity curve and a Sharpe number, with no NaN in the middle of the series.
  • You can confirm the momentum signal never uses same-day information. Check one date by hand.

Common mistakes

  • Forgetting .shift(1) on a signal. Your backtest will look amazing and be impossible to trade.
  • Starting trials.csv later. You will not remember the configurations you tried, and the Phase 7 statistics will be wrong.

Phase 1: Labels (CUSUM, triple-barrier, meta-labeling)

Read: Ch 3  ·  Build: src/labeling.py and unit tests  ·  Done when: label counts and class balance look sensible, and tests pass.

The idea

Standard ML labels every day as "up" or "down". That is a poor target: it ignores whether the move was big enough to matter, and it ignores that the price path matters, not just the end point. AFML instead:

  • Samples events, not days. The CUSUM filter only fires when the cumulative price movement has drifted past a threshold. Quiet days produce nothing.
  • Labels with barriers. From each event, you set a profit-taking barrier above and a stop-loss barrier below, plus a time limit. Whichever barrier the price hits first decides the label. This is the triple barrier.
  • Separates direction from sizing. Meta-labeling takes a simple "side" signal (long or short) and trains a second model to predict whether that side is right. You will return to this in Phase 6.

  1. Daily volatility

    Barrier widths should scale with how volatile the stock is right now. An exponentially weighted standard deviation of returns is a common choice. It reacts faster than a simple rolling window.

    ret = np.log(prices["close"]).diff()
sigma = ret.ewm(span=100).std()

  2. CUSUM filter (sample events)

    Keep two running sums: one for upward drift, one for downward drift. Each sum resets at zero whenever it goes the wrong way. When either exceeds the threshold h, record an event and reset that sum.

    def cusum_events(close: pd.Series, h: float) -> pd.DatetimeIndex:
    diff = np.log(close).diff().dropna()
    s_pos, s_neg = 0.0, 0.0
    events = []
    for t, r in diff.items():
        s_pos = max(0.0, s_pos + r)
        s_neg = min(0.0, s_neg + r)
        if s_pos > h:
            s_pos = 0.0
            events.append(t)
        elif s_neg < -h:
            s_neg = 0.0
            events.append(t)
    return pd.DatetimeIndex(events)

    This version uses one fixed h. The book sets the threshold relative to volatility at each point, which is better when volatility changes over time. Start simple, then upgrade.

  3. Triple-barrier label for one event

    Starting from an event at t0, set the upper and lower barriers as multiples of volatility. Walk forward day by day. The first barrier touched sets the label. If time runs out first, the label is 0.

    def triple_barrier(close: pd.Series, sigma: pd.Series, t0, pt: float = 1.0, sl: float = 1.0, max_bars: int = 5):
    p0 = close.loc[t0]
    s0 = sigma.loc[t0]
    upper = p0 * np.exp(pt * s0)    # profit-take level
    lower = p0 * np.exp(-sl * s0)   # stop-loss level

    i0 = close.index.get_loc(t0)
    end = min(i0 + max_bars, len(close) - 1)
    for i in range(i0 + 1, end + 1):
        p = close.iloc[i]
        if p >= upper:
            return close.index[i], +1   # profit-take hit first
        if p <= lower:
            return close.index[i], -1   # stop-loss hit first
    return close.index[end], 0          # vertical barrier: time ran out

    The function returns when the label is resolved (t1) as well as the label itself. You need t1 in Phase 2 and Phase 4, so keep it.

  4. Apply it to every event

    events = cusum_events(prices["close"], h=0.02)
rows = []
for t0 in events:
    t1, label = triple_barrier(prices["close"], sigma, t0)
    rows.append({"t0": t0, "t1": t1, "label": label})
labels = pd.DataFrame(rows).set_index("t0")

print(labels["label"].value_counts())

  5. Meta-labeling

    Pick a simple primary side, for example the sign of the momentum signal from Phase 0. Then relabel: the meta-label is 1 if the side was right, 0 otherwise. Train the classifier to predict the meta-label, not the raw direction.

    side = np.sign(mom).reindex(labels.index)      # +1 long, -1 short, from the primary rule
meta_label = (labels["label"] == side).astype(int)
meta_label = meta_label[labels["label"] != 0]  # drop time-outs, they are ambiguous

    Dropping time-outs is a judgement call. Note it in your notes, because it changes the class balance.

  6. Write unit tests

    A test should build a tiny price series where you know the answer.

    # tests/test_labeling.py
import pandas as pd
from src.labeling import triple_barrier

def test_profit_take_hit_first():
    idx = pd.date_range("2024-01-01", periods=4, freq="B")
    close = pd.Series([100.0, 100.0, 105.0, 90.0], index=idx)
    sigma = pd.Series(0.01, index=idx)          # tiny barriers, around +/-1 percent
    t1, label = triple_barrier(close, sigma, idx[0], pt=1.0, sl=1.0, max_bars=3)
    assert label == 1
    assert t1 == idx[1] or t1 == idx[2]

    Run tests with python -m pytest tests -q. Add a test for a stop-loss hit and one for a time-out.

Checkpoint

  • The number of events is much smaller than the number of days. If CUSUM fires on almost every day, h is too small.
  • Labels are not almost all one value. A heavily lopsided balance (for example 95/5) usually means the barriers are set wrong. Check the counts before you train anything.
  • Your three unit tests pass: profit-take, stop-loss, and time-out.

Common mistakes

  • Using t1 as the event time. Keep t0 (the start) and t1 (the end) separate. Phase 4 depends on that gap.
  • Computing sigma with future data. It must only use data up to t0, which ewm does by default.

Phase 2: Concurrency, uniqueness, and sample weights

Read: Ch 4  ·  Build: src/weights.py  ·  Done when: weights match a toy example you worked out by hand.

The idea

Labels overlap. Event A runs from day 1 to day 5, and event B starts on day 3. On days 3 to 5 they both describe the same price moves. If you treat them as independent, the model sees the same information twice and overfits. The fix is to weight each event by how much unique information it carries.

  • Concurrency: how many events are active on each day.
  • Uniqueness: for each event, the average of 1 / concurrency across the days it covers. An event that overlaps nobody has uniqueness 1.
  • Sample weight: uniqueness multiplied by the size of the return the event captures, normalised so the weights average 1.

Toy example (do this by hand first)

Three days. Event A covers days 1 to 2. Event B covers days 2 to 3.

DayActive eventsConcurrency c1 / c
1A11.00
2A, B20.50
3B11.00

Uniqueness of A = mean(1.00, 0.50) = 0.75. Uniqueness of B = mean(0.50, 1.00) = 0.75. Both events are equally unique here, so they get equal weight.

  1. Count concurrency

    Build a daily series where each day counts how many event windows cover it.

    def num_concurrent(t0: pd.Series, t1: pd.Series, index: pd.DatetimeIndex) -> pd.Series:
    # t0 and t1 are aligned Series: index = event start, values = event end
    c = pd.Series(0, index=index)
    for start, end in zip(t0, t1):
        c.loc[start:end] += 1
    return c

    The zip loop is fine here. There are only as many iterations as events, and each one is a simple slice.

  2. Average uniqueness per event

    def avg_uniqueness(t0: pd.Series, t1: pd.Series, c: pd.Series) -> pd.Series:
    vals = [(1.0 / c.loc[start:end]).mean() for start, end in zip(t0, t1)]
    return pd.Series(vals, index=t0.index)

  3. Turn uniqueness into a sample weight

    Weight by uniqueness times the absolute return the event captured, then scale so the mean is 1. Scaling keeps the learning rate and regularisation settings meaningful.

    captured = (prices["close"].reindex(labels["t1"]).values /
            prices["close"].reindex(labels.index).values) - 1
weights = avg_uniqueness(labels_t0, labels_t1, c) * np.abs(captured)
weights = weights / weights.mean()

    Keep the names aligned. The reindex calls give you returns in the same row order as the events, so the arithmetic matches row by row.

  4. Test against the toy example

    # tests/test_weights.py
import pandas as pd
from src.weights import num_concurrent, avg_uniqueness

def test_toy_uniqueness():
    idx = pd.date_range("2024-01-01", periods=3, freq="B")
    t0 = pd.Series(list(idx[[0, 1]]), index=[0, 1])
    t1 = pd.Series(list(idx[[1, 2]]), index=[0, 1])
    c = num_concurrent(t0, t1, idx)
    assert list(c) == [1, 2, 1]
    u = avg_uniqueness(t0, t1, c)
    assert abs(u[0] - 0.75) < 1e-9
    assert abs(u[1] - 0.75) < 1e-9

Checkpoint

  • The test above passes, and its numbers match the table you worked out by hand.
  • Weights average 1 across the dataset, and no weight is negative or NaN.

Common mistakes

  • Forgetting that t1 is inclusive. An event that ends on day 2 covers day 2. Slicing with .loc already includes the end, which matches.
  • Computing weights on the full dataset and then splitting. That is fine for weights, since they use only label timing. Just make sure you never use returns from the future to pick a model.

Phase 3: Fractionally differentiated features

Read: Ch 5  ·  Build: src/features.py  ·  Done when: features pass a stationarity test but still correlate with price.

The idea

Models need stationary inputs (statistics that do not drift over time). Prices are not stationary. Returns are, but returns throw away all the memory in the price level. Fractional differencing sits between the two. With a fraction d between 0 and 1, you keep as much memory as possible while making the series stationary enough for a model.

The goal is the smallest d that passes the ADF test. Smaller d keeps more memory.

  1. Compute the weights

    The weights start at 1 and decay. Each new weight is the previous one multiplied by (d - k + 1) / k, with a minus sign. Stop when a weight is tiny, so you only use a fixed window.

    def frac_weights(d: float, thresh: float = 1e-5) -> np.ndarray:
    w = [1.0]
    k = 1
    while True:
        w_k = -w[-1] * (d - k + 1) / k
        if abs(w_k) < thresh:
            break
        w.append(w_k)
        k += 1
    return np.array(w[::-1])   # oldest first, so the newest value gets w[0] at the end

  2. Apply the weights with a fixed window

    Each output value is a weighted sum of the last width log prices. The first few rows have no full window, so they stay NaN.

    def frac_diff(log_price: pd.Series, d: float, thresh: float = 1e-5) -> pd.Series:
    w = frac_weights(d, thresh)
    width = len(w)
    values = log_price.values
    out = np.full(len(values), np.nan)
    for i in range(width - 1, len(values)):
        out[i] = np.dot(w, values[i - width + 1 : i + 1])
    return pd.Series(out, index=log_price.index)

  3. Search for the minimum d that passes ADF

    The Augmented Dickey-Fuller (ADF) test has a null hypothesis of a unit root, meaning non-stationary. A p-value below 0.05 rejects that, so the series is stationary.

    from statsmodels.tsa.stattools import adfuller

def min_d(log_price: pd.Series, grid=np.arange(0.0, 1.0001, 0.05)):
    for d in grid:
        x = frac_diff(log_price, d).dropna()
        p_value = adfuller(x)[1]
        if p_value < 0.05:
            return round(float(d), 2), p_value
    return None, None   # no d in the grid passed: widen the grid or check the data

    The function returns None instead of guessing when nothing passes. Handle that case in your code. Do not silently pick a default.

  4. Check that memory is kept

    A stationary series that has no relationship to price is useless. Check the correlation with the original log price, over the rows where both exist.

    d, p = min_d(log_price)
fd = frac_diff(log_price, d)
both = pd.concat([fd, log_price], axis=1).dropna()
print("d =", d, "ADF p =", round(p, 4))
print("correlation with log price:", round(both.corr().iloc[0, 1], 3))

    Keep the correlation as high as you can while ADF still passes. Near zero means you differenced too much. On a synthetic random walk in testing, d = 0.4 kept a correlation of about 0.73, while d = 1.0 dropped it to about 0.02. Real prices will differ, so use this as a sanity check, not a target.

Checkpoint

  • ADF p-value is below 0.05 for the chosen d.
  • Correlation with log price is still high. The minimum d varies by stock, so expect different values across your universe. Record the chosen values in trials.csv.

Common mistakes

  • Running ADF on the raw price series instead of the fractionally differentiated one.
  • Choosing d by eye. Let the search decide, and record the result in trials.csv.
  • Ignoring the NaN rows at the start. Drop them before you fit a model, but keep the date alignment intact.

Phase 4: Purged K-Fold cross-validation with embargo

Read: Ch 7  ·  Build: src/cv.py and a leakage test  ·  Done when: a test shows no training label overlaps the test period.

The idea

Ordinary K-Fold shuffles data and splits it into folds. In finance that leaks information in two ways:

  • Overlap: a training event can run past the start of a test event, so the model learns the answer to a test question.
  • Serial correlation: observations next to the test window carry information about it.

Purging removes training events whose label window overlaps the test window. Embargo removes a further block of training events just after the test window, to cover the remaining correlation.

  1. Split into contiguous folds

    Folds are contiguous blocks in time, not random samples. That keeps the test period a real period.

    import numpy as np

folds = np.array_split(np.arange(n), n_splits)

  2. Write the purged splitter

    For each test fold, find its time window. Then drop any training event whose [t0, t1] interval overlaps that window, and drop an embargo block after it.

    # src/cv.py
import numpy as np
import pandas as pd

class PurgedKFold:
    def __init__(self, n_splits: int = 5, embargo_pct: float = 0.01):
        self.n_splits = n_splits
        self.embargo_pct = embargo_pct

    def split(self, X: pd.DataFrame, t1: pd.Series):
        # X.index holds event start times (t0); t1 must be aligned with X
        n = len(X)
        embargo = int(n * self.embargo_pct)
        indices = np.arange(n)
        t0_values = X.index.values
        t1_values = t1.values

        for test_idx in np.array_split(indices, self.n_splits):
            test_start = t0_values[test_idx[0]]
            test_end = t1_values[test_idx].max()

            # purge: any event whose interval touches [test_start, test_end]
            overlaps = (t0_values <= test_end) & (t1_values >= test_start)
            train_mask = ~overlaps
            train_mask[test_idx] = False

            # embargo: drop the block of events immediately after the test fold
            stop = min(test_idx[-1] + 1 + embargo, n)
            train_mask[test_idx[-1] + 1 : stop] = False

            yield indices[train_mask], test_idx

    Note that split is a generator. Use list(cv.split(X, t1)) if you need the splits more than once.

  3. Use it for model training

    Scikit-learn's cross-validation helpers need extra setup for sample weights, so a plain loop is clearer and easier to debug.

    cv = PurgedKFold(n_splits=5, embargo_pct=0.01)
for train, test in cv.split(X, t1):
    model.fit(X.iloc[train], y.iloc[train], sample_weight=w.iloc[train])
    p = model.predict_proba(X.iloc[test])[:, 1]
    # store p and y for this fold so you can score them later

  4. Write the leakage test

    This test is the most important one in the project. It checks the thing that matters: no training event touches the test window.

    # tests/test_cv.py
def test_no_leakage(X, t1):
    cv = PurgedKFold(n_splits=5, embargo_pct=0.01)
    for train, test in cv.split(X, t1):
        assert len(set(train) & set(test)) == 0
        test_start = X.index[test[0]]
        test_end = t1.iloc[test].max()
        train_t0 = X.index[train]
        train_t1 = t1.iloc[train]
        # no training interval may touch the test window
        touches = (train_t0 <= test_end) & (train_t1 >= test_start)
        assert not touches.any()

Checkpoint

  • The leakage test passes for every fold.
  • You can see the purge working: print how many training rows each fold removes. It should be a noticeable number, not zero, on a dataset with long labels.

Common mistakes

  • Using sklearn.model_selection.KFold or cross_val_score with default settings. They shuffle and do not purge, so your scores will be inflated.
  • Setting t1 to the event start instead of the label end. The purge then does nothing.
  • Fitting the scaler or the fracdiff d on all the data before splitting. Fit those inside each training fold.

Phase 5: LightGBM baseline and feature importance

Read: Ch 6 (skim), Ch 8  ·  Build: a model, src/importance.py  ·  Done when: importance rankings are stable across folds, not random.

The idea

A model that scores well can still be using noise. Feature importance answers "which inputs does the model actually rely on?" The book uses three methods, each with a different strength:

  • MDI (mean decrease impurity): read from the tree structure during training. Fast, but only reflects the training data, and it favours features with many possible values.
  • MDA (mean decrease accuracy): shuffle one feature on held-out data and see how much the score gets worse. Measures out-of-sample use.
  • SFI (single feature importance): train the model on one feature at a time. Shows what each feature can do alone, with no interaction effects.

If the three methods disagree wildly, or the ranking changes from fold to fold, the signal is probably noise.

  1. Train a baseline classifier

    Start with a small model. Restricting tree size and requiring many samples per leaf guards against fitting noise.

    import lightgbm as lgb

model = lgb.LGBMClassifier(
    n_estimators=200,
    learning_rate=0.05,
    num_leaves=15,
    min_child_samples=50,   # each leaf needs many events, which limits overfitting
)
model.fit(X.iloc[train], y.iloc[train], sample_weight=w.iloc[train])

  2. MDI (from the model)

    By default LightGBM counts how often each feature is used to split. Set importance_type="gain" if you want the total improvement instead, which is closer to MDI.

    mdi = pd.Series(model.feature_importances_, index=X.columns).sort_values(ascending=False)
print(mdi)

  3. MDA (on held-out data)

    For each feature, shuffle its column in the test fold, recompute the log loss, and record how much worse it got. Repeat over folds and average.

    from sklearn.metrics import log_loss

def mda_one_feature(model, X_test, y_test, w_test, col, rng):
    base = log_loss(y_test, model.predict_proba(X_test)[:, 1], sample_weight=w_test)
    X_perm = X_test.copy()
    X_perm[col] = rng.permutation(X_perm[col].values)
    shuffled = log_loss(y_test, model.predict_proba(X_perm)[:, 1], sample_weight=w_test)
    return shuffled - base   # positive means the feature helped

    Use a fixed random generator, such as rng = np.random.default_rng(42), so results are reproducible.

  4. SFI (one feature at a time)

    Train and score the model with a single feature for each column. This is a loop over columns with the same purged folds.

    def sfi_score(X_col, y, w, t1, cv):
    scores = []
    for train, test in cv.split(X_col, t1):
        m = lgb.LGBMClassifier(n_estimators=100, learning_rate=0.05, num_leaves=7, min_child_samples=50)
        m.fit(X_col.iloc[train], y.iloc[train], sample_weight=w.iloc[train])
        p = m.predict_proba(X_col.iloc[test])[:, 1]
        scores.append(-log_loss(y.iloc[test], p, sample_weight=w.iloc[test]))
    return np.mean(scores)

sfi = pd.Series({c: sfi_score(X[[c]], y, w, t1, cv) for c in X.columns})

    Log loss is negated so that a higher score means a better feature.

  5. Check stability across folds

    Compute the three rankings for each fold, then compare them. Spearman rank correlation is a simple way to measure agreement.

    from scipy.stats import spearmanr

rho, _ = spearmanr(fold1_mda, fold2_mda)
print("fold-to-fold rank agreement:", round(rho, 2))

    A rank correlation close to 1 means the importance is stable. Values near 0 mean you are looking at noise.

Checkpoint

  • The top features agree roughly across MDI, MDA, and SFI.
  • Rank correlation across folds is high. There is no universal threshold, so compare it against the rank correlation of shuffled importances as a rough noise baseline.
  • Your score beats a random or coin-flip baseline on the held-out folds.

Common mistakes

  • Trusting MDI alone. It is computed on training data, so it can rank a feature highly that the model memorised.
  • Forgetting to use the purged folds for MDA and SFI. Importance computed on leaking folds is meaningless.
  • Tuning many hyperparameters at once. Keep the model simple at this stage so the importance results are easy to read.

Phase 6: Bet sizing and discretization

Read: Ch 10  ·  Build: src/sizing.py  ·  Done when: a sized strategy is compared with a fixed-size one on the same folds.

The idea

The classifier gives a probability that the side is right. Instead of betting the same amount every time, bet more when the probability is high and less when it is near 50 percent. The book converts the probability into a bet size between -1 and 1 using a normal distribution. Then you round the size to a few levels, so you do not trade tiny changes every day.

  1. Convert a probability into a bet size

    For a binary outcome, the z-statistic measures how far the probability is from a coin flip. The normal CDF turns that into a size between -1 and 1.

    from scipy.stats import norm

def bet_size(p: np.ndarray) -> np.ndarray:
    p = np.clip(p, 1e-6, 1 - 1e-6)   # avoid division by zero at 0 and 1
    z = (p - 0.5) / np.sqrt(p * (1 - p))
    return 2 * norm.cdf(z) - 1

    A probability of 0.5 gives size 0. A probability of 0.9 gives a size of about 0.82. The clip is there because the formula breaks at exactly 0 or 1, and failing silently would hide a real problem.

  2. Apply the side from the primary model

    Multiply by the side from Phase 1 (+1 or -1). The sign of the position comes from the primary rule, and the size comes from the classifier.

    position = side * bet_size(p_meta)

  3. Discretize

    Round to steps of 0.1 (or whatever step you choose). This cuts turnover, because small changes in probability no longer cause trades.

    def discretize(m: np.ndarray, step: float = 0.1) -> np.ndarray:
    return np.round(m / step) * step

  4. Compare against fixed size

    Run the same folds with two strategies: fixed size (always +1 or -1 with the side) and sized (the discretized position). Keep everything else identical so the comparison is fair. Record both in trials.csv.

    fixed_pos = side
sized_pos = discretize(side * bet_size(p_meta))

fixed_ret = fixed_pos * ret_next
sized_ret = sized_pos * ret_next

    Here ret_next is the return over each event's holding period, aligned to the events. Make sure it starts after the signal, as in Phase 0.

Checkpoint

  • Bet sizes stay within -1 and 1, with no NaN.
  • Probabilities near 0.5 give sizes near 0.
  • You have a side-by-side comparison, and you can explain in one sentence why the sized version does or does not win.

Common mistakes

  • Calibrating the classifier's probabilities on the same data you evaluate on. Use out-of-fold predictions only.
  • Looking only at the sized strategy's return. Also check turnover. A sizing method that trades constantly will lose to costs, even with a better gross return.

Phase 7: Backtest statistics (CPCV, PSR, DSR, PBO)

Read: Ch 11, 12, 14  ·  Build: src/backtest.py (CPCV), src/stats.py  ·  Done when: you have a distribution of Sharpe ratios, not a single number.

The idea

One backtest gives one Sharpe ratio, and that number is almost always too optimistic. Three problems:

  • Single path: one historical path is one sample of what could have happened. Combinatorial purged cross-validation (CPCV) builds many paths from the same data.
  • Selection: if you tried many configurations and kept the best, its Sharpe is inflated. The Deflated Sharpe Ratio (DSR) corrects for the number of trials in trials.csv.
  • Luck and shape: the Probabilistic Sharpe Ratio (PSR) asks how likely the true Sharpe is above a benchmark, given the length of the sample and the skew and fat tails of returns.

The Probability of Backtest Overfitting (PBO) estimates how often the best in-sample configuration performs below median out-of-sample.

  1. Build CPCV splits

    Divide the timeline into N groups. Choose k of them as test groups in every combination. Each combination gives a test set, and the test groups are stitched into several full backtest paths. Each path is a complete history you can compute a Sharpe on.

    from itertools import combinations
from math import comb

N, k = 6, 2
test_combos = list(combinations(range(N), k))
n_paths = k * comb(N, k) // N   # number of full paths, here 5
print(len(test_combos), "splits,", n_paths, "paths")

    Purging and embargo from Phase 4 still apply at every boundary between a test group and a training group.

  2. Compute a Sharpe for each path

    Stitch the out-of-sample returns for each path in time order. Compute a Sharpe on each one. You should end up with a list of Sharpe ratios, not one number. This list is your result for Phase 7.

    path_sharpes = [sharpe(path_returns[p]) for p in paths]
print("median:", np.median(path_sharpes), "  5th pct:", np.percentile(path_sharpes, 5))

  3. Probabilistic Sharpe Ratio (PSR)

    PSR is the probability that the true Sharpe is above a benchmark sr_star. It adjusts for sample length n, skew g3, and kurtosis g4. Use per-period Sharpe here, not annualised.

    from scipy.stats import skew, kurtosis

def psr(r: pd.Series, sr_star: float = 0.0) -> float:
    sr = r.mean() / r.std()                     # per-period Sharpe
    n = len(r)
    g3 = skew(r)
    g4 = kurtosis(r, fisher=False)              # raw kurtosis, not excess
    denom = np.sqrt(1 - g3 * sr + (g4 - 1) / 4 * sr ** 2)
    return norm.cdf((sr - sr_star) * np.sqrt(n - 1) / denom)

    The fisher=False argument matters. SciPy's default is excess kurtosis, and the formula needs the raw value. Using the default quietly gives the wrong answer.

  4. Deflated Sharpe Ratio (DSR)

    DSR is PSR with the benchmark raised to the Sharpe you would expect from the best of N pure-luck trials. N comes from trials.csv. The variance of Sharpe estimates across those trials is also needed.

    EULER_GAMMA = 0.5772156649

def expected_max_sr(sr_var: float, n_trials: int) -> float:
    return np.sqrt(sr_var) * (
        (1 - EULER_GAMMA) * norm.ppf(1 - 1 / n_trials)
        + EULER_GAMMA * norm.ppf(1 - 1 / (n_trials * np.e))
    )

trials = pd.read_csv("trials.csv")
sr_star = expected_max_sr(trials["sharpe"].var(), len(trials))
dsr = psr(best_returns, sr_star=sr_star)

    Two warnings: the trials' Sharpe values must be per-period too, to match. And trials.csv must include every configuration you actually tried, or the correction is too small.

  5. Probability of Backtest Overfitting (PBO)

    PBO uses the same data split many ways to see whether the best in-sample choice tends to stay good out of sample. The procedure, called CSCV:

    1. Split the returns into an even number S of time blocks.
    2. For each way of picking half the blocks as in-sample, find the configuration with the best in-sample Sharpe.
    3. Find where that configuration ranks out of sample among all configurations.
    4. PBO is the fraction of splits where it ranks below the median.

    PBO close to 0.5 means your selection process is no better than chance. Lower is better. This takes more code than the others, so write it as its own function with a test on synthetic random returns, where PBO should come out near 0.5.

Checkpoint

  • You report a distribution of Sharpe ratios (median and a lower percentile), not one figure.
  • PSR and DSR are computed from the same per-period returns, and the DSR is lower than the raw Sharpe would suggest.
  • Your PBO test on random returns comes out near 0.5.

Common mistakes

  • Reporting the best path's Sharpe. Report the distribution.
  • Leaving out failed or abandoned experiments from trials.csv. That is the most common way DSR is wrong in practice.
  • Mixing annualised and per-period Sharpe values in the same formula.

Mistakes that ruin everything

These cause the most damage and are the hardest to notice. Check for each one before you trust a result.

MistakeWhat it looks likeHow to prevent it
Look-ahead biasResults look too good, especially early in the sample.Shift signals before trading. Compute every feature using only data up to that row.
Overlapping labels leakingCross-validation scores far above what the model achieves live.Use PurgedKFold with t1 and an embargo (Phase 4). Keep the leakage test.
Survivorship biasBacktest only holds companies that survived to today.Include delisted tickers and point-in-time index membership from Phase 0.
Selection biasYou kept the best of many configurations.Log every trial in trials.csv and report DSR.
Silent fallbacksA function returns a default when it fails, and you never notice.Raise an error or return None explicitly, and handle it. Do not hide failures.
Ignoring costsStrategy looks profitable but trades heavily.Subtract a transaction cost per unit of turnover before reporting results.
